# 通用企业智能客服 Agent Demo 六阶段开发计划

本项目不按“大企业级系统”一开始做，也不拆得过碎。正式开发按 6 个阶段推进：

```text
基础聊天闭环 -> 知识库上传与文档解析 -> RAG 核心闭环 -> 客服基础功能 -> 管理后台 -> Tool Calling / 企业系统模拟
```

核心目标保持不变：

```text
企业文档上传 -> RAG 检索问答 -> 引用来源 -> 无答案处理
```

## 技术栈

- React：前端聊天窗口和管理页面。
- FastAPI：后端 API 服务。
- DeepSeek API：主要 LLM 调用，采用 OpenAI-compatible 接口方式封装。
- Embedding：用于文档 chunk 和用户问题向量化。
- Chroma：基础 Demo 默认向量数据库，便于快速跑通 RAG。
- PostgreSQL + pgvector：V1 增强版方向，更贴近企业项目。
- RAG：企业知识库检索增强问答主流程。
- 简单 Tool Calling：基础版用于知识缺口记录、转人工入口；增强版扩展订单查询和工单创建。

---

## 阶段 1：基础聊天闭环

目标：先让系统能跑、能聊。

功能区块：

- React 聊天界面
- FastAPI 后端
- DeepSeek API / OpenAI-compatible LLM 调用封装
- 流式输出
- 无 API Key 时本地演示回复

不做：

- RAG
- 权限
- 管理后台
- 文档上传

验收标准：

```text
用户输入问题
↓
后端调用 DeepSeek 或本地演示回复
↓
前端显示 AI 回复
```

当前状态：已完成。

---

## 阶段 2：知识库上传与文档解析

目标：让企业文档能进入系统，并解析出后续 RAG 可使用的文本。

功能区块：

- 上传 PDF / TXT / Markdown
- 文档列表
- 文档状态：`processed`、`failed`
- 文档详情 / 解析预览
- 删除文档
- 文本解析
- 简单文本清洗

说明：

- 基础版采用同步处理，上传完成后直接返回 `processed` 或 `failed`。
- `pending`、`processing`、`indexed` 更适合异步任务队列和向量索引阶段，放到阶段 3 或 V1 增强。
- 阶段 2 不做文本切片、Embedding、Chroma 入库和检索。

验收标准：

```text
上传一个售后政策 PDF / TXT / Markdown
↓
系统能解析出文本
↓
知识库页面能看到文档和处理状态
↓
可以查看解析预览
↓
可以删除文档
```

当前状态：已完成最小闭环，需持续用真实企业样本文档补充测试。

---

## 阶段 3：RAG 核心闭环

目标：完成项目最重要的核心价值。

功能区块：

- 文本切片
- Chunk overlap
- chunk metadata：`document_id`、`filename`、`chunk_index`、`page_number`、`created_at`
- Embedding
- Chroma 向量入库
- 文档索引状态：`indexed`、`failed`
- Top-K 检索
- 相似度分数
- Prompt 拼接
- 基于知识库回答
- 引用来源
- 无依据拒答
- 基础 RAG 日志

不做：

- 混合检索
- Rerank
- 查询改写
- 多路召回
- PostgreSQL + pgvector

验收标准：

```text
上传售后政策
↓
用户问退款问题
↓
系统检索相关片段
↓
AI 基于片段回答
↓
回答显示来源
```

补充验收：

- 知识库中没有答案时，不编造。
- 日志中能看到本次命中的 chunks、分数和来源。
- 更换文档后，RAG 流程仍可复用。

阶段价值：完成后项目已经具备简历和面试展示价值。

---

## 阶段 4：客服基础功能

目标：让系统更像真实客服产品，但仍不做重企业集成。

功能区块：

- 聊天记录
- 历史会话
- 用户反馈：有帮助 / 没帮助
- 知识缺口记录
- 转人工入口

验收标准：

```text
用户问了一个知识库没有的问题
↓
系统不胡说
↓
记录到知识缺口
↓
提示可转人工
```

补充验收：

- 用户可以查看历史对话。
- 用户可以对回答反馈。
- 无答案问题可以进入知识缺口列表。

---

## 阶段 5：管理后台

目标：让企业能管理这个系统，让 Demo 更像产品。

页面区块：

- Dashboard
- 知识库管理
- 文档管理
- 对话记录
- 反馈记录
- 知识缺口列表
- RAG 检索日志

Dashboard 基础指标：

- 文档数量
- 今日对话数
- 用户反馈数量
- 知识缺口数量
- 转人工请求数量

权限：

- 基础 Demo 只做普通用户和管理员。
- 客服人员角色放到 V1。

验收标准：

```text
管理员能看到：
文档数量
对话记录
AI 使用了哪些知识片段
用户反馈
未解决问题
```

---

## 阶段 6：Tool Calling / 企业系统模拟

目标：展示 Agent 能接企业系统。

先做 Mock，不接真实 ERP / CRM / OA。

功能区块：

- Mock 订单查询 API
- Mock 创建工单 API
- 工具调用记录
- 工具结果转自然语言回复

验收标准：

```text
用户问：我的订单 10001 到哪了？
↓
Agent 调用 get_order_status
↓
返回：订单已发货，预计明天送达
```

面试表达：

> 当前版本用 Mock API 模拟订单系统，真实企业中可替换为 ERP、CRM、OA 或工单系统接口。

## 节奏建议

| 阶段 | 时间 | 结果 |
|---|---:|---|
| 阶段 1 | 1-2 天 | AI 聊天能跑 |
| 阶段 2 | 2-3 天 | 文档能上传解析 |
| 阶段 3 | 4-7 天 | RAG 问答核心完成 |
| 阶段 4 | 2-4 天 | 客服功能完善 |
| 阶段 5 | 3-5 天 | 管理后台可展示 |
| 阶段 6 | 3-5 天 | Agent 工具调用演示 |

正常节奏：3-4 周可以做出不错的 Demo。继续打磨 README、截图、Docker、测试问题集后，4-6 周可以变成可投简历的作品。

## 当前优先级

先完成阶段 1-3：

1. 系统能聊天。
2. 文档能上传解析。
3. 系统能基于企业知识库完成 RAG 问答、展示引用来源，并在无依据时拒答。

阶段 3 完成后，项目即可具备 GitHub、简历和面试展示价值。
